# 我的跨 AI 共用個人檔案

這份檔案讓不同 AI 助手了解我的工作情境與協作偏好，減少重複說明，並延續已確認的需求與決策。

> 整理日期：2026-11-09。內容根據可用的過往聊天摘要、專案記憶與本次對話整理，並非完整聊天紀錄。這是待本人校閱的個人化初稿；職稱、學歷、年資及技術熟練程度尚未確認。專案成果是歷史摘要，不代表目前仍在使用或已正式部署。

## 個人簡介與背景

- 我主要在 Windows 環境中與 AI 協作，處理實際工作需求、程式工具與資料輸出。
- 過往協作主題包含 Excel 報表與庫存比對、Python 桌面工具、AI 影像與短影片製作，以及跨專案知識管理。
- 我關注成果是否能實際使用、是否保留原有資料與功能，以及後續能否維護、追溯與回退。
- 稱呼、正式職稱、產業背景、學歷與年資：待本人補充；請勿從專案名稱或 GitHub 帳號自行推測。

## 工作與學習習慣

- 開始前先釐清需求、假設、不確定處與風險，列出簡短計畫及每一步的驗證方法。
- 有多種做法時，先簡述差異並推薦最穩妥方案；需求有歧義時先確認，不自行補齊關鍵條件。
- 偏好最小、精準、可逆的修改。只處理本次需求，不順手重構、不增加未要求的功能。
- 修改重要檔案或設定前先備份；保留原始檔案、資料、既有功能及不明用途的設定。
- 重視實際輸出的驗收：報表要檢查生成檔案，影片要檢查畫面與聲音，打包程式要確認交付版本。
- 操作教學請依執行順序拆成小步驟。尤其是 PowerShell／Git，請說清楚目前目錄、每行指令用途與預期結果，必要時一次只提供一行。
- 固定學習時段與長期學習進度：待本人補充。

## 溝通風格偏好

- 使用繁體中文，先說重點，再提供必要的理由與步驟。
- 用簡單、清楚、具體的文字；技術細節應能幫助理解或操作，避免堆砌術語。
- 明確區分「已驗證」「歷史紀錄」「推論」「待確認」，不要把未知狀態寫成成功或通過。
- 發現問題時說明原因、影響與下一步；無法測試時說明限制並提供人工驗收方式。
- 完成回報需包含：修改了哪些檔案、修改內容、如何驗證，以及未完成或需人工確認的事項。
- 如有無關問題，可列為建議，不要擅自修改。

## 項目經驗與成果

以下描述的是我與 AI 協作推進過的工作，不等同於我獨立撰寫了所有程式；未列出的職責、商業成效及量化效益仍待確認。

### 庫存比對與 Excel 報表工具

- 協作整理需求、庫存與相關來源資料，建立 Windows 桌面比對工具及 Excel 結果輸出。
- 歷史專案記憶記載：V1.1 將主結果整合至同一份 Excel，並在漏開訂單明細中加入品名。
- 重視新增欄位時保留既有計算與扣抵邏輯；交付時核對實際報表及打包版本。
- 目前使用狀況、公開作品連結與可公開量化成果：待本人確認。

### AI 影像與直式影片製作

- 使用 ComfyUI 與 Python 媒體工具協作處理影像、浮水印、配樂及直式影片輸出。
- 2026 年 10 月的歷史紀錄顯示：曾完成約 5 秒、1080 × 1920、30 fps 的直式影片，含平滑縮放與背景音樂，並驗證輸出規格、聲音及畫面變化。
- 當次成果仍有來源影像與裁切限制；原始 ControlNet 相容性問題未完整解決，不應概括為整套工作流已修復。

### 跨專案與跨 AI 個人知識管理

- 使用 Obsidian 與 Markdown 整理穩定偏好、工作流程、長期規劃、重要決策與專案摘要。
- 建立 `ai-personal-profile` 公開倉庫，以 README 作為跨 AI 參考入口、Issues 追蹤待辦、Git 保存修改歷史。
- 區分公開個人檔案與內部專案記憶，避免將私人資料、機密設定或完整聊天逐字稿放入公開倉庫。

## 給 AI 助手的協作提醒

- 將本檔案作為背景參考；當前對話中的最新明確要求優先於過往摘要。
- 提供方案、編輯檔案、正式部署與對外發布是不同範圍，請確認操作符合當次授權。
- 安全、權限、部署或風險接受事項若未獲確認，維持待確認狀態；不要自行填入核准人或將未知改為通過。
- 打包 EXE 時，除非明確要求，不改動核心業務邏輯與資料檔。
- 不把密碼、Token、API key、私密金鑰、內部安全設定或完整個資寫入公開檔案或永久記憶。
- 無法讀取連結或記憶時請直接說明，不要聲稱已讀取；不同 AI 不會因為本倉庫存在而自動同步記憶。

## 使用與維護

- 與 AI 協作時，提供本 README 內容或連結，並確認 AI 能讀取目前版本；本倉庫不會自動同步到所有 AI。
- 在 [Issues](https://github.com/WalterC801029/ai-personal-profile/issues) 建立待辦，寫明目標、驗收條件與相關章節；完成更新後附上 commit 連結並關閉 Issue。
- 每次修改以 Git commit 記錄目的；在 GitHub 的 History 或本機 `git log --oneline` 查看歷史。
- 如需撤銷某次已提交修改，使用 `git revert <commit-SHA>` 新增反向提交，再執行 `git push`，保留原有歷史。

### 本地同步

首次下載：

```powershell
git clone https://github.com/WalterC801029/ai-personal-profile.git
cd ai-personal-profile
```

每次編輯前，先在工作目錄乾淨時更新：

```powershell
git pull --ff-only
```

修改 README 後提交並推送：

```powershell
git diff
git add README.md
git commit -m "docs: 更新個人檔案"
git push
```

本機未提交的編輯不會自動進入 Git 歷史；推送需要具有此倉庫寫入權限的 GitHub 身分驗證。
